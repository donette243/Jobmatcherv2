# JobMatcher

JobMatcher — веб-приложение для поиска вакансий и подбора наиболее подходящих предложений на основе навыков, опыта и профессионального профиля пользователя.

Приложение позволяет пользователю создать профиль, загрузить резюме, автоматически извлечь из него навыки, искать вакансии и получать рекомендации с расчётом соответствия вакансий профилю.

## Возможности

- Регистрация пользователя
- Авторизация и аутентификация
- Восстановление пароля
- Управление профессиональным профилем
- Загрузка резюме в формате PDF или DOCX
- Автоматический анализ резюме
- Извлечение информации и навыков из резюме
- Просмотр и поиск вакансий
- Расчёт процента соответствия вакансии профилю
- Рекомендации вакансий на основе профиля пользователя
- REST API на FastAPI
- Веб-интерфейс на React

# Установка и запуск

## 1. Клонирование репозитория

```bash
git clone https://github.com/donette243/Jobmatcherv2.git
cd Jobmatcherv2
```

## 2. Настройка Backend

Перейти в директорию backend:

```bash
cd backend
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать виртуальное окружение.

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Windows CMD:

```cmd
.venv\Scripts\activate
```

После активации в начале строки терминала должно появиться:

```text
(.venv)
```

## 3. Установка зависимостей Backend

Все необходимые зависимости находятся в `requirements.txt`.

```bash
pip install -r requirements.txt
```

Дополнительная ручная установка библиотек не требуется.

## 4. Настройка MySQL

Перед запуском приложения необходимо иметь работающий сервер MySQL и создать базу данных для JobMatcher.

Например:

```sql
CREATE DATABASE jobmatcher;
```

Параметры подключения указываются через переменную `DATABASE_URL` в файле `.env`.

## 5. Переменные окружения

В директории `backend` создать файл `.env` на основе `.env.example`.

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Windows CMD:

```cmd
copy .env.example .env
```

Пример конфигурации:

```env
DATABASE_URL=mysql+pymysql://USER:PASSWORD@localhost:3306/jobmatcher

JWT_SECRET_KEY=replace-with-a-random-secret-key-at-least-32-bytes-long
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60

SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_FROM=jobmatcher@example.com
SMTP_USE_TLS=false

FRONTEND_URL=http://localhost:5173
```

Необходимо заменить `DATABASE_URL` и `JWT_SECRET_KEY` собственными значениями.

`.env` содержит локальные и секретные настройки и не должен публиковаться в GitHub.

## 6. Миграции базы данных

После настройки MySQL и `.env` применить миграции:

```bash
alembic upgrade head
```

Миграции создают и обновляют необходимую структуру базы данных.

## 7. Mailpit для восстановления пароля

Для локальной разработки и тестирования восстановления пароля используется Mailpit.

Docker Desktop должен быть запущен.

Из корневой директории проекта выполнить:

```bash
docker compose up -d
```

Текущий `docker-compose.yml` запускает Mailpit.

Mailpit SMTP:

```text
localhost:1025
```

Веб-интерфейс Mailpit:

```text
http://localhost:8025
```

Письма, отправленные приложением в режиме локальной разработки, отображаются в Mailpit и не отправляются на реальные внешние почтовые адреса.

Для остановки Mailpit:

```bash
docker compose down
```

## 8. Запуск Backend

Из директории `backend` установить путь к `src`.

Windows PowerShell:

```powershell
$env:PYTHONPATH="src"
```

Windows CMD:

```cmd
set PYTHONPATH=src
```

Запустить сервер:

```bash
uvicorn jobmatcher.main:app --reload
```

Backend API:

```text
http://127.0.0.1:8000
```

Swagger:

```text
http://127.0.0.1:8000/docs
```

Backend необходимо оставить запущенным во время работы frontend.

## 9. Настройка и запуск Frontend

Открыть новый терминал и из корневой директории проекта перейти в:

```bash
cd frontend
```

Установить зависимости:

```bash
npm install
```

Запустить frontend:

```bash
npm run dev
```

Frontend будет доступен по адресу:

```text
http://localhost:5173
```

## 10. Основной сценарий работы

После запуска приложения можно проверить основной пользовательский сценарий:

1. Создать новый аккаунт.
2. Войти в аккаунт.
3. Перейти в Dashboard.
4. Заполнить профессиональный профиль.
5. Загрузить резюме в формате PDF или DOCX.
6. Проверить обработку резюме и извлечение навыков.
7. Перейти к списку вакансий.
8. Выполнить поиск вакансий.
9. Перейти в раздел рекомендаций.
10. Проверить рассчитанный процент соответствия вакансий профилю.
11. Выйти из аккаунта.
12. Проверить защиту страниц, требующих авторизации.
13. Снова войти и проверить сохранность данных профиля.

Для локального тестирования вакансии могут быть предварительно добавлены в базу данных.

## 11. Восстановление пароля

Для проверки полного сценария восстановления пароля:

1. Убедиться, что Mailpit запущен через Docker Compose.
2. Создать пользователя или использовать существующий аккаунт.
3. На странице авторизации нажать «Забыли пароль?».
4. Указать email зарегистрированного пользователя.
5. Открыть `http://localhost:8025`.
6. Найти письмо восстановления пароля в Mailpit.
7. Перейти по ссылке из письма.
8. Указать новый пароль.
9. Войти в приложение с новым паролем.

Ссылка восстановления имеет ограниченный срок действия.

### Использование внешнего SMTP

Сервис отправки писем не привязан к Mailpit и может работать с внешним SMTP-сервером.

Для этого необходимо настроить соответствующие переменные окружения, например:

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your-user
SMTP_PASSWORD=your-password
SMTP_FROM=your-email@example.com
SMTP_USE_TLS=true
FRONTEND_URL=http://localhost:5173
```

Реальные SMTP-логины и пароли нельзя сохранять в репозитории.

Mailpit используется в проекте как воспроизводимый локальный SMTP-сервер для разработки и проверки сценария восстановления пароля.

### Отправка писем реальным пользователям

Mailpit используется только для локальной разработки и тестирования. Он перехватывает письма и отображает их в локальном веб-интерфейсе, поэтому такие письма не доставляются на реальные адреса Gmail, Outlook и других почтовых сервисов.

Для отправки писем реальным пользователям JobMatcher поддерживает внешний SMTP-сервер. Для этого необходимо указать данные SMTP-провайдера в локальном файле `.env`:

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your-user
SMTP_PASSWORD=your-password
SMTP_FROM=your-email@example.com
SMTP_USE_TLS=true
FRONTEND_URL=http://localhost:5173
```

После настройки внешнего SMTP существующий сервис отправки писем будет отправлять ссылку восстановления пароля на реальный email пользователя.

SMTP-провайдером может быть любой совместимый внешний почтовый сервис. Конкретные параметры подключения зависят от выбранного провайдера.

Логины, пароли, API-ключи и другие секретные данные нельзя сохранять в GitHub. Они должны находиться только в `.env` или в защищённых переменных окружения сервера.

Для проверки проекта без внешнего почтового аккаунта рекомендуется использовать Mailpit.

```bash

```

```text

```

Он необходим для тестирования чтения и обработки CV.

Текущий ожидаемый результат:

```text
5 passed
```

Тесты проверяют основные компоненты обработки CV, профиля, вакансий и matching.
